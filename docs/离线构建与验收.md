# 离线构建与验收

知页的桌面端、SQLite Core、本机 REST 服务、TypeScript SDK 和 stdio MCP 适配器均可从当前项目源码构建。锁文件固定了 Cargo 和 npm 的依赖。桌面端的 WebView 由操作系统提供。构建和日常使用无需知页账号、付费编辑器插件或模型密钥。[第三方组件说明](../THIRD_PARTY_NOTICES.md) [完整开发计划](../个人资源管理系统_完整开发Plan_v2.0.md)

归档入口要求文件和目录位于项目实际目录树内。若输入使用 Windows 目录联接、符号链接或其他重解析点，请将需要纳入归档的源码放进项目的普通目录。遇到目录读取失败时归档会报出错误。ZIP 写入或自检出现错误后，可使用相同的新输出文件名重试。[归档回归](../scripts/package-source.test.py)

## 在联网时准备工具和缓存

使用 Node.js 24 和项目锁定的 Rust `1.100.0`。Windows x64 还需要 MSVC、Visual Studio C++ 构建工具、Windows SDK 和 WebView2 Runtime。macOS 需要 Xcode 构建工具。先在与离线目标相同的系统和架构上安装工具链，再用同一版本源码的两个锁文件准备依赖。不同架构的 npm 原生包需分别准备。[npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/) [Cargo fetch](https://doc.rust-lang.org/cargo/commands/cargo-fetch.html)

在联网的 Windows x64 源码目录中运行以下命令。可按实际路径设置缓存位置。

```powershell
$env:NPM_CONFIG_CACHE = 'D:\zhiye-cache\npm'
$env:CARGO_HOME = 'D:\zhiye-cache\cargo'
npm.cmd ci --no-audit --no-fund
cargo.exe fetch --locked --target x86_64-pc-windows-msvc
```

在联网的 Apple Silicon 源码目录中，可将 `--target` 换成 `aarch64-apple-darwin`。使用 `npm ci --cache /你的路径/npm --no-audit --no-fund` 和 `CARGO_HOME=/你的路径/cargo cargo fetch --locked --target aarch64-apple-darwin` 将依赖放入指定目录。给离线机器带上源码、npm 缓存中的 `_cacache` 和 Cargo 缓存中的 `registry`。离线机自身还要装好相应工具链。锁文件变更后，按新锁文件预热并重新验收。[Cargo 离线模式](https://doc.rust-lang.org/cargo/commands/cargo-fetch.html#manifest-options)

## Windows x64 离线源码构建

从新的源码目录开始，避免引用旧的 `node_modules`、`dist` 和 `target`。在 PowerShell 中指向准备好的缓存。

当前 Windows 交接 ZIP 携带与冻结源码锁文件对应的 `dependencies\npm` 和 `dependencies\cargo`，以及用于生成两种安装包的 `dependencies\nsis`。准备好 Windows 工具链后，从本机 NTFS 解包目录按验收包命令构建。[验收包使用说明](Windows验收包.md#以缓存从源码构建)

当 `cargo.exe` 不在 PATH 中时，脚本会查找 `%LOCALAPPDATA%\ZhiyeDevToolchain`。已设置的 `CARGO_HOME` 和 `RUSTUP_HOME` 会保留，未设置的变量各自使用备用工具链目录。

```powershell
$env:NPM_CONFIG_CACHE = 'D:\zhiye-cache\npm'
$env:CARGO_HOME = 'D:\zhiye-cache\cargo'
$env:NPM_CONFIG_OFFLINE = 'true'
$env:CARGO_NET_OFFLINE = 'true'
npm.cmd ci --offline --no-audit --no-fund
.\scripts\windows-dev.ps1 test
.\scripts\windows-dev.ps1 build
```

`test` 会构建 SDK 和 MCP，并运行桌面前端、集成和 Core 测试。`build` 把前端嵌入桌面可执行文件，将 Cargo 本次报告的应用复制为 `artifacts\Zhiye-<版本>-win-x64.exe`。设置 Cargo 目标或目标目录时，脚本会沿用本次构建的产物路径。想单独构建脚本接入组件可运行 `npm.cmd run build:integrations`。出现 `ENOTCACHED` 或 Cargo 依赖缺失时，在对应目标的联网环境中按原锁文件补齐缓存。[Windows 构建入口](../scripts/windows-dev.ps1)

当前 Windows 构建入口可直接从 UNC 共享目录调用。脚本优先复用指向项目的现有 Windows 网络盘符，需要时临时映射共享目录，结束时恢复调用目录并移除本轮盘符。单独运行 `npm.cmd ci` 时，从 Windows 盘符进入支持工作区目录链接的源码目录。当前 SuperSophie NAS 实测拒绝创建该链接，可从冻结源码在本机 NTFS 临时目录安装依赖及构建，把源码修改、交付文件和复验记录集中保存到共享目录。[共享目录入口实测](../.verify/windows-unc-build/复验.md)

常规 NSIS 安装包用 `.\scripts\windows-dev.ps1 installer` 构建。可先在联网时使用同一 Windows 账户和同版本源码运行一次常规打包，保留 Tauri 下载的 NSIS 工具和插件，供断网构建复用。常规安装包在目标机缺少 WebView2 时会取用微软引导程序，也可在断网前预装微软独立运行时。[Tauri 的 WebView2 安装模式](https://v2.tauri.app/distribute/windows-installer/#webview2-installation-options)

用 `.\scripts\windows-dev.ps1 offline-installer -WebView2InstallerPath $runtime` 构建内置微软 x64 WebView2 Evergreen 独立运行时的安装包。可从验收包提取对应版本。入口校验运行时的 SHA-256，并把离线包写入独立输出目录。安装完成后可在断网状态复验本地核心功能。[提取运行时并重建安装包](Windows验收包.md#从源码重建两种安装包) [断网安装步骤](Windows验收.md#a17-断网安装) [微软离线部署](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution#offline-deployment)

### 使用构建目录内的 NSIS 工具

当前工作源码的 `-UseLocalNsisTools` 选项让打包器读取构建目标下的 `.tauri\NSIS`，适合使用专用缓存的断网构建。准备与锁定 Tauri CLI 2.12.4 匹配的整套 NSIS 3.13 工具目录，其中包含 Tauri NSIS 插件 0.5.3。可从使用同版 CLI 成功打包的机器复制其工具目录。脚本在构建前核对必要文件及 Tauri 固定的工具指纹，缓存缺失或版本不符时提示实际目录。[Tauri 2.12.4 的工具版本与校验](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.12.4/crates/tauri-bundler/src/bundle/windows/nsis/mod.rs)

在新构建目标中，给两种安装包分别放置工具缓存。将 `$runtime` 指向从对应验收包提取的 WebView2 独立安装程序。

```powershell
$env:CARGO_TARGET_DIR = 'D:\zhiye-test\target'
$nsis = 'D:\zhiye-cache\NSIS'
foreach ($tools in "$env:CARGO_TARGET_DIR\.tauri", "$env:CARGO_TARGET_DIR\offline-installer\.tauri") {
    New-Item -ItemType Directory -Path $tools -Force | Out-Null
    Copy-Item -LiteralPath $nsis -Destination $tools -Recurse
}
.\scripts\windows-dev.ps1 installer -UseLocalNsisTools
if ($LASTEXITCODE -ne 0) { throw '常规安装包构建失败。' }
.\scripts\windows-dev.ps1 offline-installer -WebView2InstallerPath $runtime -UseLocalNsisTools
```

## 离线运行验收

2. 创建和编辑页面并保存。退出再打开，搜索正文，定位到原块。复验数据库的属性、筛选或公式，以及附件原件和 PDF 文字层。
