# 知页数据格式

## 工作空间

数据目录中的每个工作空间由一个 UUID 子目录和 `workspace.sqlite` 组成。当前的 `PRAGMA user_version` 为 22。Core 在数据根目录持有独占写入锁。存储实例关闭时显式释放该锁。打开格式 1 至 21 的工作空间时，先在 `upgrade-backups/` 生成 `<工作空间 ID>-v<旧格式>.sqlite` 与同批次的整库恢复包，再以单事务升级。附件原件使用该工作空间的 `blobs/<SHA-256>`。

SQLite 22 新增 `sync_state`、`sync_objects`、`sync_outbox` 和 `sync_pending`，记录同步游标、启用状态与服务地址、各页面的服务端版本与一致时的状态指纹、未确认的推送操作和暂存的远端变化。未启用同步的工作空间中这些表为空。整库恢复包恢复为新工作空间时清空这些表。[自托管同步](自托管同步.md#本机数据)

SQLite 17 为 `pages` 增加可空的 `cover`，记录本页图片原件的 `attachmentId` 和 `mediaType`。图标 `icon` 与封面随修订保存。只有本页不超过 24 MiB 的 PNG、JPEG、GIF、WebP 和 BMP 可作为封面。模板创建页面时将封面引用映射到新页面的附件 ID。设为「无封面」后仍可在附件列表和已有修订中取回原件。

页面以稳定 UUID 标识，父页字段为 `parentId`。一次页面写入同时提交标题、正文、块 ID、记录属性与修订。保存要求调用方提交当前 `revision`。相同内容沿用原修订。页面移入回收站时按 `trashRootId` 标记同批次子树。恢复旧修订时，将当时的标题、正文及记录属性写入新修订，保留当前层级与历史。

批量移动、归档与恢复逐项校验页 ID 和预期修订，在一次 SQLite 事务内写入。移动和归档时，同时选中上级与子页只处理上级分支。数据库记录的位置随所属数据库调整。归档为移入回收站，原有独立的归档批次会保留。批量恢复同时选中记录和其已归档的数据库时，记录保留原有归属。

清空回收站在写事务内核对已确认的页面、修订、受影响记录和数据库专属模板，再移除归档页及其修订。存活记录的新修订只剔除指向已删记录的关系。SQLite 19 的 `deleted_collections` 与 `deleted_records` 保留被删数据库 ID、记录页 ID 与归属，供保留历史和模板验证。恢复历史或应用模板时过滤已删目标。已失去相应范围的集成游标按范围变化失效。

SQLite 19 的 `blob_quarantine` 记录首次发现原件无引用的时间。回收站和所有保留修订引用的原件由附件元数据保护，模板原件从快照核对。在途备份、内容导出和原件发布由协调锁或 SQLite 写事务保护。检查后等待七天，确认时再次比对候选文件和引用。重新引用的原件结束本次保留期。整库恢复包包含快照需要的原件。恢复空间按实际出现的无引用原件重新登记时间。[清理操作](故障恢复.md#清空回收站与清理附件原件)

保存失败时可将编辑缓冲另存为 `.zhiye-draft.json`。`format` 为 `zhiye.page-draft`，`formatVersion` 为 `1`。顶层的 `workspaceId`、`pageId`、`baseRevision` 表示来源和最近一次确认的页面修订。`draft` 包含当时的 `title` 与原生 `blocks`，包括未知块、页内引用和附件引用 ID。文件写入用户所选位置，不经过页面提交。操作见 [故障恢复](故障恢复.md)。

记录属性表单将草稿导出为 `.zhiye-record-draft.json`，`format` 为 `zhiye.record-draft`，`formatVersion` 为 `1`。文件记录 `workspaceId`、`collectionId`、`pageId` 和表单打开时的 `baseRevision`。`draft` 中的 `title`、`schemaRevision` 和 `properties` 保留表单提交值，关联属性使用 `add` 和 `remove` 数组。可在文本编辑器查看 JSON，并把所需值重新填入记录。[记录属性保存失败](故障恢复.md#记录属性保存失败)

## 集成与修订来源

SQLite 格式 6 增加集成和资源授权。每个工作空间独立保存令牌的 SHA-256 摘要、展示用指纹、动作权限、授权资源、最近访问时间和撤销状态。已发放令牌只能访问所属工作空间。最近访问时间最多每 30 秒更新一次。

SQLite 格式 20 为 `integrations` 增加可空的 `expires_at`，值为 Unix 毫秒。有到期时间的令牌仅在当前时间早于该值时通过鉴权。旧授权升级后以 `NULL` 表示手动撤销。整库恢复保留有效期和来源记录，恢复空间中的令牌统一禁用。

外部实际修改的页面修订在原事务内记录集成 ID 和操作 ID。幂等记录按集成和请求键索引，保存请求摘要及原提交结果至少 7 天。重试时先核对当前权限。内容 ZIP v4 保留页面和修订快照。集成配置、令牌摘要、来源审计以及幂等记录目前留在工作空间 SQLite 中，内容恢复后的集成列表为空。[本机 API v1](本机API.md)

SQLite 格式 7 的 `workspace_state` 保存查询的单调提交序号、游标签名密钥和本机 API 单文件上传上限。页面、数据库、记录、附件或授权内容提交时，序号在同一事务内推进。后台索引进度和最近访问时间更新保持原序号。查询向客户端返回不透明快照标识。ZIP 恢复创建新的工作空间和独立签名密钥。

SQLite 格式 8 增加资源变更表、数据库与附件的编目修订、归档时的授权凭据和改动建议。业务提交或回滚时，变更事件与业务数据同步提交或回滚。归档前记录当时有权读取的集成及其授权版本。授权内容或已有页面的覆盖范围改变时，更新相应集成的版本。编目和变更游标由工作空间私有密钥认证加密。变更行保留至少 31 天，每天首次写入时可清理旧事件的连续前缀。[SQLite AUTOINCREMENT](https://www.sqlite.org/autoinc.html) [RustCrypto XChaCha20Poly1305](https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/#xchacha20poly1305)

SQLite 格式 14 增加 PDF 提取状态、按页文字和 FTS5 索引。一个附件的文字结果和状态在同一事务发布，绑定当前原件 SHA-256 和索引代次。重建会推进代次，应用退出后待处理原件可继续提取。ZIP 格式 4 保留权威附件元数据与原件，从 ZIP 恢复时重新生成 PDF 索引。[PDF 检索](PDF检索.md)

建议记录提交者、底稿修订及投影 ETag、候选操作、审阅快照、状态和期限。重新预览会生成新的审阅版本。正式页面修订、建议接受状态、来源和变更事件一并提交。迁移格式 7 时，现有页面、数据库和附件从首次编目取得。内容 ZIP 恢复同样从新工作空间的编目初始化，集成、建议和旧游标留在来源工作空间。

SQLite 格式 10 增加 `derived_jobs`、`derived_job_references` 和 `feed_derived_audience`。源块提交、源页标题变化、归档及恢复按引用索引记录待处理位置，引用预览用到的行内页面链接也参与归档和恢复的检查。待处理任务包含两侧原始修订号、可读依赖集合和授权版本，源正文仍从既有的修订快照读取。后台在同一事务发布事件并确认本批位置。失败后保留未确认项并退避重试。派生事件与普通事件共用现有序号、游标和保留窗口，事件回收时一并删除对应授权记录。原生包恢复从新空间的编目起点开始。

API 上传先校验当前权限并暂存字节，提交时再次检查令牌、目标页权限、修订、大小和幂等键。附件元数据、目标页新修订和来源在一个 SQLite 事务提交。原件在提交前按 SHA-256 发布，后续由同一工作空间复用。

## 原生工作空间包

应用导出 `.zhiye.zip`。ZIP 内包含 UTF-8 的 `manifest.json`，以及每个原件的 `blobs/<SHA-256>`。文件条目按原样存储。清单顶层字段如下。

| 字段 | 含义 |
|---|---|
| `format` | 固定为 `zhiye.workspace` |
| `formatVersion` | 桌面导出使用 `7`，含数据库或记录墓碑时使用 `8`，含历史属性定义时使用 `9` |
| `sha256` | `data` 的 SHA-256 十六进制校验值 |
| `data.content.workspace` | 来源工作空间的 `id`、`name` |
| `data.content.pages` | 页面快照，包含页面元数据、块数组、记录属性和可选的 `cover` |
| `data.content.revisions` | 选中的修订快照。保存全部历史和仅保存当前修订的包都包含每页当前版本。v9 的部分旧修订还包含 `historicalProperties` |
| `data.attachments` | 文件元数据，包括页 ID、附件 ID、名称、大小、类型和原件哈希 |
| `data.databases.definitions` | 数据库定义，包含容器页 ID、属性 Schema、Schema 修订和保存视图 |
| `data.databases.records` | 记录归属，包含 `pageId`、`collectionId`、`createdAt` |
| `data.databases.tombstones` | ZIP v8 的已删数据库 ID 与记录归属 ID，用于校验保留历史 |
| `data.library.navigation` | 收集箱页 ID、收藏和最近访问序列，条目含页 ID 和时间戳 |
| `data.library.importReceipts` | 导入方式、原目的地、文件名、SHA-256 与输出页 ID |
| `data.library.templates` | 模板名称、适用数据库、按父页优先排序的页面快照、记录属性与附件清单 |
| `data.export` | v7 的范围声明。含 `scope`、`history`、`downgrades`、`omissions` |

校验值计算使用 `serde_json` 将 `data` 的对象键递归排序后紧凑编码。数组顺序保留。恢复和合并均校验清单及原件哈希、层级、记录归属、属性和附件引用。恢复先在暂存目录写库，事务提交后发布新空间。新工作空间使用新的 ID，内部对象和回收站批次沿用包内 ID。

`scope` 固定为 `workspace`。默认 `history` 为 `all`，取消历史选项时为 `current` 并在 `omissions` 中列出 `priorRevisions`。仅导出当前修订时，沿用每页当前修订号，恢复或合并后可继续生成下一修订。原生块保留其结构，`downgrades` 为空数组。`omissions` 记录集成、修订归因、建议、变更流、搜索索引、计算缓存、迁移批次与备份策略。

合并为包内对象分配新 ID，顶层页面归入同一导入分支。页面、块、附件、封面及数据库视图的结构化引用重写到副本。属性选项、对向关联、公式属性引用和视图配置随各自数据库映射。找不到对象的非强制链接分配独立的不可用目标。未知块保留原负载及附加字段。模板使用独立快照 ID，重名时添加编号。缺失原件或关系属性指向无效记录时拒绝导入。原件先暂存并校验后发布为不可变文件，内容与批次完成状态在同一 SQLite 事务提交。

SQLite 格式号与备份包格式号独立。ZIP v6 包含封面引用及其图片原件，ZIP v5 纳入 Notion 与 Obsidian 迁移凭据，ZIP v4 包含库内导航、模板和通用导入凭据，ZIP v3 包括数据库，ZIP v2 包括页面和附件。Core 兼容写入函数 `write_workspace_archive` 可为无墓碑和历史属性定义的内容生成 v5 或 v6。JSON v1 的 `data` 直接包含 `workspace`、`pages` 与 `revisions`。ZIP v2 至 v9 和 JSON v1 均可恢复或合并。清单或 v1 JSON 上限为 64 MiB，ZIP 原件合计上限 2 GiB，单附件上限 100 MiB，单页正文 JSON 上限 1 MiB。

## 整库恢复包

`.zhiye-recovery.zip` 使用独立的 `zhiye.recovery` 格式。清单 `recovery.json` 的 `formatVersion` 当前为 1，包含 `sqliteVersion`、来源空间 `workspace`、恢复点 `capture`，以及 `database` 和 `blobs` 中每份文件的 SHA-256 与大小。文件条目包括清单、`workspace.sqlite` 及按快照的附件和模板引用选出的 `blobs/<SHA-256>`。

快照通过 SQLite Online Backup API 生成。写 ZIP 前在副本中撤销所有集成、替换令牌摘要和游标密钥，再清理空闲页。修订归因、审计、建议状态、库内设置和数据库中的其他历史信息随快照保存。应用级备份策略记录在数据根目录的 `backup-policy.json`，各空间的恢复点和失败记录位于 `backup-state/<工作空间 ID>.json`。[SQLite Online Backup API](https://www.sqlite.org/backup.html)

读取整库包时，先核对压缩包条目、文件大小和哈希，再在隔离目录验证 SQLite 结构、完整性、引用和附件。应用比对结构与内建版本定义，之后才能对暂存副本进行升级。恢复空间使用新的工作空间 ID 和游标密钥，并保留内部对象 ID。校验失败时丢弃暂存副本。单个 SQLite 条目上限为 16 GiB，清单上限为 16 MiB，最多 100,000 个不同的原件。恢复的逻辑校验还会使用与页面及历史规模相关的内存。[SQLite 不受信任数据库文件指南](https://sqlite.org/security.html) [使用与恢复步骤](故障恢复.md)

## 迁移批次

SQLite 15 保留已有 `import_receipts`，增加 `notionZip` 和 `obsidianVault` 两种导入凭据。凭据的 `sha256` 对应暂存清单的摘要，涵盖有序条目路径、已留存内容的哈希和跳过说明。ZIP v5 保存这些凭据。

SQLite 18 为 `migration_batches` 增加 `nativeContent`，保留旧批次。`migration_batches` 先记录批次、来源和应用会话。准备阶段校验原件，发布事务同时写入页面、库定义、记录、附件、导入凭据与完成状态。新会话将上一会话留下的准备状态展示为中断。取消和失败信息记录在目标 SQLite 中。Notion 和 Obsidian 的逐文件报告可通过桌面另存。[迁移导入](迁移导入.md)

## 搜索索引

`search_pending` 在页面写入事务中登记待处理页。桌面打开工作空间后分批更新 `search_entries` 与 SQLite FTS5。检索仅返回当前修订、仍在活动范围的页面。索引可从正文重建，恢复原生包后会重新生成索引。

查询按字面字符串匹配，统一使用 Unicode 小写。三个字符起走 FTS5 trigram，短查询在派生文本中用子串匹配。代码中的引号、冒号等属于普通文本。每页优先返回标题命中，否则返回文档顺序中的第一处正文命中。单次最多返回 20 页。正文命中附稳定块 ID，片段保留原始字符。属性条件沿用数据库视图的字段和运算符校验。[SQLite FTS5](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

## 数据库与记录

数据库用 `id` 标识，`containerPageId` 对应页面树中的数据库入口。每条记录是该容器页的直属子页。普通页面的数据格式沿用旧版。记录的当前页面和修订额外带有以属性 UUID 为键的 `properties` 对象。

| 属性类型 | 值 |
|---|---|
| 标题 | 使用页面的 `title` |
| 文本、数字、复选框 | 分别为字符串、JSON 数字、布尔值。数字绝对值上限为 2⁵³−1 |
| 日期、日期时间 | 全天日期为 `YYYY-MM-DD`。日期时间为精确到秒且带 `Z` 或 `±HH:mm` 的 RFC 3339 字符串 |
| 网址 | HTTP 或 HTTPS 网址 |
| 状态、单选 | 选项 UUID |
| 多选、附件 | 选项 UUID 或本记录页附件 UUID 的数组 |
| 创建时间、修改时间 | 由记录创建时间与当前页面的 `updatedAt` 提供，单位为 Unix 毫秒 |

省略属性键表示未填写。清空时，空文本、空数组和 `null` 归一为缺省。数字 `0` 与布尔值 `false` 是已填写值。属性和选项改名沿用原 ID。记录属性更新同时核对页面和属性 Schema 的修订。

SQLite 格式 21 支持转换可填写属性的类型。预览与确认绑定属性 Schema、相关记录、模板和视图。确认保留属性 ID，在同一事务提交 Schema、受影响的记录修订、模板和视图设置。受影响的旧修订在可选的 `historicalProperties` 数组中保存原属性定义，同一个修订的 `properties` 保留原值。历史恢复按最新定义转换并保留原修订。内容 ZIP v9 校验旧定义与旧值，合并时也重映射历史中的字段、选项及附件 ID。[属性类型转换](数据库视图.md#转换属性类型)

每个保存视图拥有独立的 `id`、`name`、`type`、`revision` 和 `settings`。设置包含单条 `filter`、单字段 `sort` 和可选 `groupBy`。高级视图使用可选的 `layout` 保存日期字段、封面字段或起止字段及默认缩放。内置标题字段以 `title` 标识，其余字段用属性 ID。日期时间比较使用对应的绝对时间，界面按 UTC 投影到日期范围。全天日期沿用其文本日期。日期范围参与分页前筛选，视图共享记录页。

SQLite 12→13 升级及旧 ZIP 恢复会在原三种固定视图上附加日历、画廊和时间线。原视图 ID、设置和修订保留。视图管理只修改数据库配置。日历与时间线拖动在同一事务校验视图与记录修订，并提交选定日期属性。[使用说明](数据库视图.md)

### 记录关联

`relation` 属性定义中使用 `relation.collectionId` 指向同空间的目标数据库。双向关联的两个属性通过 `inversePropertyId` 指向对方。记录属性保存规范排序、无重复的目标记录 ID。双向增删为两端实际变化的记录分别生成修订，并在同一事务提交。通过历史恢复关联时也同步相应的反向项。字段名称可独立修改，稳定标识继续用于写入及依赖查找。

SQLite 格式 11 的 `relation_edges` 从记录属性维护源页、属性、目标页索引。归档后保留边，恢复原记录时原边重新可用。可见变化按 `derived.invalidated` 交付。原生 ZIP v4 带上关系定义、两侧记录值和修订。恢复时核对目标数据库归属及现有双向边一致性，重建关系索引。

记录模板保留有效关联。应用模板时，指向新复制记录自身的内部关系映射至新标识。CSV 只保存可用关联的标题并在导出报告标出降级。追加 CSV 时，关联列作为无匹配项列入导入报告。

### 计算属性

属性定义的 `calculation` 包含 `type`。公式存储 `expression`，其中 `prop` 使用稳定属性 ID，标题使用 `title`。汇总存储 `relationPropertyId`、`function` 和 `targetPropertyId`。计数的目标属性为 `null`。原始记录及历史修订保存输入。计算结果在读取事务中按当前规则和授权求值。

SQLite 格式 12 的 `computed_dependencies` 由属性定义建立本地和跨记录依赖。原生 ZIP v4 保存计算定义，恢复时校验关联、目标数值属性和公式引用，再重建依赖索引。提交输入变化时记录受影响主体的派生待办，`derived_job_computed` 与现有派生队列共用批次确认和重试。计算版本和原始数据的保存前置条件分别见[本机 API](本机API.md#计算属性)。CSV 保存导出时的结果及降级报告。[计算规则](计算属性.md)

SQLite 16 的 `computed_jobs` 记录源提交版本、输入字段和当时的授权版本。`computed_record_before` 和 `computed_schema_before` 保留受改动输入的前一个状态，直到旧任务完成。后台沿当前和待办历史依赖定位记录，按提交顺序比较授权表示，再将缓存、派生事件和批次确认一次提交。升级保留 SQLite 15 中尚待投递的任务。

`computed_cache` 记录读取主体、授权版本、计算时间和授权可见输入的校验值。读取时按当前授权核对。源和授权版本稳定时直接使用缓存。源版本前进时只校验实际访问的可读字段、规则及关联成员。可见结果失效且有新任务时返回待计算状态。原生 ZIP v5 保存计算规则及权威数据，缓存和队列由新空间从当前数据建立。[后台重算](计算属性.md#后台重算)

## 页面与块

页面字段有 `id`、`parentId`、`title`、`revision`、`updatedAt`（Unix 毫秒）、`icon`、`trashRootId`、`blocks`。

块的例子如下：

```json
{
  "id": "5e84b82c-55de-410a-aa56-b1573e61fe99",
  "type": "paragraph",
  "schemaVersion": 1,
  "payload": {
    "inline": [
      { "type": "text", "text": "读书笔记", "marks": [{ "type": "bold" }] },
      { "type": "pageReference", "pageId": "40806dbc-c4db-4f65-93e2-4104bc4b249f", "label": "资料" }
    ]
  },
  "children": []
}
```

`paragraph`、`heading` 保存行内内容，标题额外使用 `level`。列表、待办和引用使用 `children`。有序列表保存起始编号 `start` 和可选编号样式 `type`，待办项使用 `checked`。代码块保存 `text` 和可选 `language`。分割线的 `payload` 为空对象。未知类型、较新块版本或超出编辑器支持的块显示为占位，并随原生包保留数据。桌面 IPC 用字符串传递 JavaScript 无法原样表示的块数据。页内引用限定于当前工作空间。

正文块移动重排页的 `blocks` 或所在容器的 `children`，保留块及后代的 ID、内容和引用。新顺序随页面修订一次提交。编辑器为可继续输入而补出的末尾光标段落，在实际写入内容或成为正文结构后才进入持久化数组。已有的空段落和 ID 正常保留。

Markdown 是单页标题与正文的通用导出，使用标题、段落、列表、代码与 `[[页面名]]` 等表示。复杂或陌生块会降级为提示。完整的页和块 ID、数据库、属性、历史与附件随原生备份包迁移。

### 正文内容块

SQLite 格式 13 和原生 ZIP 格式 4 中可以包含折叠、提示、公式、目录、附件和数据库视图。各块以 `schemaVersion: 1` 声明数据形状。目录只保存块身份。从备份或模板复制页面时，正文引用的同页附件须存在，模板将附件引用重新绑定到新页的附件 ID。历史中的附件引用同样纳入备份校验。[序列化与 Markdown 示例](内容块.md)

### 块引用

`blockReference` 版本 1 的 `payload` 只有源页的 `pageId` 和源块的 `blockId`，`children` 为空。引用按当前工作空间解析，源块正文从读取时的源页获取。源页改动只提交源页的修订。源块移除或源页归档期间保留引用描述，恢复原标识后可再次解析。

SQLite 格式 9 增加 `page_links` 及 `block_ids.reference_anchor`。升级时从页面正文回填行内页面引用、块引用和可读块位置。每次写入页面时在同一事务中更新，两项索引可随 ZIP 恢复重建。套用模板时，指向模板子树内部的块引用映射为新页与新块 ID，指向外部的标识沿用原值。

### 正文图片、表格和网页地址

- `attachmentImage` 版本 1 的 `payload` 包含 `attachmentId`、`mediaType` 和 `alt`，`children` 为空。附件关联需属于当前页，媒体类型需与原件一致。图片说明单独参与检索，可定位到图片块。图片改名保留附件 ID。创建模板副本时，块中的附件 ID 随本页新的附件关联映射。
- `table` 的子块为 `tableRow`，每行包含 `tableCell` 或 `tableHeader`。行、单元格及其中的段落拥有各自的稳定块 ID。单元格可保存 `align`、`colspan`、`rowspan` 和 `colwidth`。常规 Markdown 表格保留内容和列对齐。包含合并单元格等结构的表格导出为普通行列，并在 Markdown 中给出提示。ZIP 保留原始结构。
- 网页链接是文本的 `{ "type": "link", "href": "https://example.org/" }` 标记。正文支持经验证的 HTTP 和 HTTPS 地址。页面引用沿用 `pageReference`。
- `collectionView` 版本 1 的 `payload` 保存同空间的 `collectionId` 和 `viewId`，`children` 为空。嵌入页保存身份，按当前视图设置读取记录。删除目标视图后仍保留嵌入块，Markdown 中降级为占位或授权数据库链接。
- 保存失败时的 Markdown 草稿保留文字和图片说明，可从页面附件另外取回原件。结构化草稿可保留原生块。[保存故障与恢复](故障恢复.md)

## 通用导出

| 格式 | 导出内容 | 核对转换及原始身份 |
|---|---|---|
| Markdown | 当前页标题与正文，封面以图片显示，引用的图片、PDF 等原件使用相对路径 | 配套目录的 `导出报告.txt` 记录源页 ID 和修订、块转换、原始页面与块链接、原件名称、路径及 SHA-256 |
| HTML | UTF-8 离线网页，显示文字、列表、表格、封面及本地图片。页面／块引用可打开知页源位置 | 配套目录记录转换和原件哈希。折叠转引用，公式显示 LaTeX 源码，目录为静态内容，嵌入视图及未知块有占位 |
| CSV | 数据库或保存视图匹配的记录行、可交换的属性值和属性引用的附件 | 配套目录的 `导出报告.txt` 记录行数、属性转换、结构损失及附件映射 |
| 原生内容包 | 页面、块、视图、关系、附件和历史的开放格式 | 依靠包清单和内容哈希校验，在独立工作空间按原始身份恢复 |

移动 Markdown 或 HTML 时把同目录的配套文件夹一起带走。折叠和提示块转为引用，公式保留源码，目录变为静态内容，嵌入视图与未知块使用占位。用报告中的知页链接在源工作空间定位，使用原生工作空间包转移页面树、原始块结构、图标、属性及历史。导出过程中出现原件读取、校验或写入错误时，会保留已存在的输出。[内容块导出示例](内容块.md#markdown-导出示例)

HTML 使用文档内样式和相对原件路径。渲染时将原始 HTML 转为文字，仅保留生成的下划线和换行标签。文档的内容安全策略限制脚本、框架和自动加载的外网资源。正常 HTTP(S) 网页链接可由读者主动打开。[W3C 内容安全策略](https://www.w3.org/TR/CSP3/)

## 导入、侧栏与模板

Markdown 导入接受 UTF-8 的 `.md` 和 `.markdown`，支持 BOM、标题、段落、列表、待办、引用、代码、GFM 表格和常用行内格式。一次最多选择 32 个文件，每个文件不超过 1 MiB。相对文件名和 Wiki 链接在同批选择的文件中按唯一名称匹配。HTTP 和 HTTPS 地址生成网页链接。失配链接、标题锚点、图片引用与原始 HTML 按报告降级，原始字节保存在页面附件。

CSV 导入使用逗号分隔的 UTF-8 文件，支持 BOM、带引号字段、双引号转义和字段内换行。每个文件上限 4 MiB 和 10,000 行数据。新建库最多 48 个自定义列，追加模式按现有字段名称和属性类型转换。日期使用 `YYYY-MM-DD`，选择项使用选项名，多选可用分号或 JSON 字符串数组。转换失败和未匹配的值保留在数据库页的 CSV 原件。列宽不匹配或标题无效的行在报告中列出并跳过。行号对应源文件中的物理行，跨行记录使用起始行号。引号结构损坏会拒绝整个文件。导入成功后可从报告直接查看原件，另存的报告记录原件名、页面和附件 ID。

CSV 导出为带 BOM 的 UTF-8 文件，使用 CRLF 和双引号转义。可选全部有效记录或当前视图的所有匹配记录。视图筛选与排序复用数据库查询规则，分组展开为数据行。标题与属性名用作表头，单选和状态使用显示名称，多选使用 JSON 字符串数组，时间属性使用 Unix 毫秒。导入多选时优先解析 JSON 数组。

附件型属性导出为相对路径的 JSON 数组。文件旁的 `zhiye-csv-…` 目录包含原件和 `导出报告.txt`。同内容附件共享导出的原件，报告保留原附件名与路径的对应。若原件读取或写入出错，已有 CSV 可继续使用。页面正文、历史、视图设置和属性定义等完整结构随原生包保留。

导入凭据保存在 `import_receipts`。同一工作空间、导入方式、目的地、原文件名和字节哈希一致时，重复导入指向原结果。导入提交时同步写入页面、原件关联和凭据。报告可另存为文本，原件作为附件参与备份。

收集箱以 `workspace_inbox.page_id` 指向普通页面或数据库。收藏和最近访问存储页面 ID，最多保留 50 个近期访问。回收站里的入口暂时隐藏，恢复页面后重新可见。

模板以快照保存，单空间最多 128 个模板，单模板最多 64 页和 8 MiB 的正文及附件清单。应用时为页、块和附件关联分配新 ID。已知的页内链接随模板子树映射，链接到同空间其他页面时保留原目标。记录模板只应用到所属数据库，并映射附件属性的 ID。模板支持普通子页，保存含子数据库的分支时会提示缩小范围。更新模板供之后创建的新页面使用。
