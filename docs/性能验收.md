# M5 性能验收

依据开发方案第 9.2 节和 A18。参考环境为 Windows x64、16 GiB 内存、本机 SSD。其他平台的报告注明实际硬件、操作系统、WebView 或浏览器、构建配置和缓存条件。[开发方案](../个人资源管理系统_完整开发Plan_v2.0.md#92-数据集与性能口径)

## 固定数据

M2 基线由 10,000 条记录页、100,000 个段落、一个数据库容器和 1,000 个 1 KiB 原件组成。逻辑夹具的 SHA-256 为 `107fb70e9bcd39ca6db88459050a780d703540e4ad36b9e5de1098297a03e875`。比较时使用同一组查询、命中数和 50 行筛选排序样例。另加入带 200 个基础段落的普通页面用于编辑器测量，报告分别列出两部分数量。[M2 原始报告](../.verify/kb-015/benchmark.json)

压力探测使用 100,000 个页面和 1,000,000 个基础块。生成数据、首次索引、查询、页面树和应用启动分开记录。

## 测量口径

| 操作 | 观察终点 | 门槛 |
|---|---|---|
| 进程冷启动 | 新应用进程启动至首个普通页正文编辑器可输入 | p95 ≤ 3 秒 |
| 普通页面打开 | 在未读取过该页正文的 UI 会话触发导航至标题和正文可输入 | p95 ≤ 500 毫秒 |
| 全文首屏 | 提交固定查询至有结果或无匹配状态，核对预期结果数，上限 20 条 | p95 ≤ 1 秒 |
| 数据库首屏 | 打开预设状态筛选与序号降序视图至表格前 50 行可交互 | p95 ≤ 1 秒 |
| 输入响应 | 后台索引待办大于 0 时，可信输入事件至正文显示变更的下一帧 | p95 ≤ 50 毫秒 |
| 本机 HTTP | 有效的普通读取令牌请求与接收完整响应，解析结果并校对授权范围 | 记录 p50、p95 和错误率 |

按最近秩计算 p50 和 p95。进程冷启动记录首轮及后续的 OS 缓存条件。全文和数据库样本在索引完成后采集，输入样本另起重建索引阶段。维持源方案设定的门槛，并保留迟缓样本、超时和错误。

全文从输入事件开始，在匹配结果提交后的动画帧取时间戳，同时测量界面与 Core 之间的往返。输入响应只收录真实浏览器键盘事件，并要求采样期间待索引页数至少推进一批。首屏结果数、排序首条记录及授权外查询结果在计时的同一轮验证。

### 从源码复验

Windows 使用 [Windows 验收入口](Windows验收.md#固定数据与压力复验)。`perf-build` 构建调试测量程序。`windows.mjs` 顺序生成基线、测量原生启动与本机 HTTP、采集原生 WebView2 交互并做十万页压力测试。交互脚本在附着到桌面 WebView2 后重载文档，以捕获实际 Tauri IPC。冷启动值来自独立重启的桌面进程。结果目录应在本机 SSD。

原生 WebView2 十万页压力验收先检查进程打开的首个可编辑正文，再刷新文档采集 IPC。`nativeFirstEditorObservedMs` 含启动进程和附着调试连接，`browserPageLoadToEditorMs` 来自随后的追踪刷新。两次编辑器等待都使用 12 秒阈值。失败报告记录阶段及当时的文档、编辑器和告警状态。[同版启动追踪](../.verify/windows-pressure-startup/复验.md)

### Chromium 联调与原生启动复验

在本机 SSD 上准备两个空的验收目录。以下命令在项目根目录运行，`baseline-dir` 和 `pressure-dir` 分别代表这两个数据根。压力测试需要为 SQLite 文件、事务文件和 WebView 预留磁盘空间。

```sh
npm ci
npm run build:ui
cargo build --locked -p zhiye-core --examples
cargo build --locked -p zhiye-desktop --features custom-protocol,performance-probe
./target/debug/examples/m5_baseline baseline-dir > baseline-core.json
node scripts/performance/native.mjs target/debug/zhiye-desktop baseline-dir baseline-core.json baseline-native.json
node scripts/performance/browser.mjs baseline-dir baseline-core.json baseline-browser.json
./target/debug/examples/m5_pressure pressure-dir > pressure-core.json
node scripts/performance/browser.mjs pressure-dir pressure-core.json pressure-browser.json pressure
```

用 `ZHIYE_TEST_CHROMIUM` 指定可运行的 Chromium 或 Chrome。测试脚本依次执行以减少 I/O 和渲染竞争。两份合成数据均关闭自动备份，浏览器脚本会在普通页输入验收文字。原生冷启动脚本读取使用 `performance-probe` 构建的调试程序在首个编辑器绘制后写出的信号，随后终止本轮进程。

压力夹具包含多个目录、固定的正文词及唯一定位词。它通过 Core 创建空工作空间，再批量填入合成页面、块身份和首版历史。索引和查询仍走 Core 正常入口。生成耗时用于复刻夹具，普通用户逐次保存耗时需单独测量。
