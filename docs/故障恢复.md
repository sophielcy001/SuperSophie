# 保存故障与恢复

## 编辑过程中出现保存失败

1. 先保留编辑窗口。编辑器显示「已保存」时，这一版已经提交到本机 SQLite。「等待保存」「正在保存」和「保存失败」对应编辑缓冲或正在提交的内容。
2. 如有可用空间，点击保存错误旁的「导出草稿」，把缓冲中的标题、正文、块 ID 和引用另存为 `.zhiye-draft.json`。磁盘写满时选择另一块有空间的磁盘。「另存 Markdown」适合直接打开查看或重新导入文字。
3. 释放工作空间所在磁盘的空间后点击「重试」。发生修订冲突时，点击「对比版本」分别选择要保留的标题和正文。页面历史会显示成功提交的修订。

Windows 上，如果卷还有可用空间但仍提示「存储空间不足」，也要检查当前账户在该 NTFS 卷上的磁盘配额。可以先把草稿导出到另一张可写的卷，释放当前账户的配额或由管理员调整配额，再在原页面点击「重试」。

正在编辑的页面随分支进入回收站时，可打开「回收站」恢复该分支。草稿会留在当前页面。恢复后使用「对比版本」，按读到的最新修订保存所选内容。

原页已永久移除或需要结束本次编辑时，可先导出草稿，再点保存错误旁的「关闭页面」。选择「返回草稿」可继续编辑，选择「放弃草稿并关闭」会清除本次未保存的修改。

关闭窗口或在 macOS 通过应用菜单退出时，知页先尝试提交当前草稿。仍有保存错误时，窗口会保留，供重试或导出。

结构化草稿记录 `workspaceId`、`pageId` 和 `baseRevision`，供核对来源和基准版本。附件属性保留对应的引用 ID，原件可从原页面或工作空间备份取回。

macOS 上可将草稿、导出文件和备份保存到已挂载的 SMB 共享目录。导出失败时，应用保留原位置的主文件和配套文件。检查共享目录是否在线、可写且有剩余空间，再选择同一位置重试。[通用导出与配套目录](数据格式.md#通用导出)

## 记录属性保存失败

属性表单遇到版本冲突时会保留已填内容。点「对比版本」按字段选择，再提交到核对过的最新修订。对比后如有更新，回到原草稿重新对比。记录已移除、属性定义已变化或存储写入失败时，可用「导出草稿」把提交值及其基准另存为 `.zhiye-record-draft.json`。[字段选择](数据库视图.md#解决记录属性冲突) [草稿格式](数据格式.md)

## 进程中断后重新打开

重新启动知页并打开原有工作空间，查看页面内容和「历史」。已提交的修订可以从 SQLite 读回，搜索索引待处理时会继续构建。此前单独导出的草稿可用于核对或找回尚待提交的文字。

## 创建整库恢复包

在侧栏打开「备份与恢复 → 创建整库恢复包」，选择应用数据目录以外的保存位置。生成的 `.zhiye-recovery.zip` 包含一致性数据库快照、历史、集成审计、工作空间配置和快照引用的附件原件。可以直接把这个文件复制到另一块磁盘或另一台电脑。

在 Windows 中也可以在系统文件窗口选择可写的 UNC 共享目录，或在「自动备份」中选择这个目录。日常工作空间和 SQLite 保存在本机磁盘。共享目录不可用时，打开「备份与恢复」查看失败原因，恢复目录后点击「立即运行备份」。

「导出工作空间」生成用于迁移页面、数据库和附件的 `.zhiye.zip` 内容包。数据库需要交换为通用格式时，可使用 Markdown 与 CSV 导出。

## 调整自动备份

1. 每个工作空间默认启用每日自动备份。知页运行时检查 UTC 日期，当天在所选目录已有成功的自动备份时复用这份备份。当天关闭了应用，下一次运行时按当日检查。
2. 可在「自动备份」选择目录、调整保留份数或关闭日常自动备份，再点击「保存备份设置」。设置适用于同一数据目录中的各工作空间。默认目录是数据根目录下的 `backups`，与原数据共用磁盘。整盘损坏会同时影响两份数据。
3. 默认保留最近七个有备份的日期，以及最近四个有备份的 ISO 周中各周最新的一份。两个保留规则可命中同一份文件。每日可设 1 至 365 份，每周可设 0 至 52 份。每份自动备份在目标目录下有一个带日期的子目录。成功写入后，知页清理当前目标目录里由本空间管理的到期恢复包。
4. 「最近成功」可展开查看文件路径。目录断开、不可写或空间不足时，面板显示失败原因。恢复目标目录后可以点击「立即运行备份」。今天需要另外保存一个时间点时，用「创建整库恢复包」。

### 当日恢复包的校验

0.35.0 起，自动检查会识别恢复包大小变化。大小相同而修改时间变化时，会重新校验包内容。旧记录第一次参与复用时也会校验。点击「立即运行备份」会核对当天恢复包的 SQLite 快照和附件哈希。

当天缺少可用恢复包时，知页会尝试生成新包。检测到问题的旧文件保留在原位置，清理旧备份的提示会显示错误。每日和每周的保留规则按有效副本计数。安装候选的验收状态见对应版本的发布说明。[当前安装候选](发布说明.md#已知限制和验收状态)

## 从备份恢复到独立空间

1. 使用侧栏「备份与恢复 → 从备份恢复」。可以打开手动、自动或升级前的 `.zhiye-recovery.zip`，也可打开 `.zhiye.zip` 内容包和旧版 `.zhiye.json`。
2. 应用校验后创建名字带「（恢复）」的新工作空间。页面、记录、正文块和附件沿用各自的 ID，原空间及快照之后提交的内容仍可单独打开。
3. 核对页面、历史与附件。整库恢复保留已记录的集成来源及授权记录，恢复空间中的旧集成全部禁用。启用本机 API 并按恢复空间需要分别创建新授权。

需要在独立数据目录做演练时，可在启动前设置 `ZHIYE_DATA_DIR`。日常数据目录、支持的构建方式及复验记录见 [README](../README.md) 和 [开发进度](../开发进度.md)。

## 合并到当前工作空间

1. 切换到目标工作空间，选择「备份与恢复 → 合并内容包」，打开 `.zhiye.zip` 或旧版 `.zhiye.json`。整库包使用「从备份恢复」入口。
2. 合并成功后会打开名称以「（导入）」结尾的新分支。包内数据库、页面、附件、历史与模板使用各自的新 ID。失配链接仍显示不可用。源收藏随新页面加入。普通模板重名时添加编号。
3. 在「备份与恢复」展开最近一次合并查看页数、原件、修订及提示。校验期间可以取消。失败、取消或中断后，可从同一入口重新选择来源。每次成功合并建立一个新分支。

## 清空回收站与清理附件原件

1. 打开当前工作空间的「回收站」，选择「清空回收站」。复核永久删除的页数、分支数及受影响的记录或数据库专属模板。确认后，已删除的页面及其修订可从清空前保存的对应备份取回。确认期间回收站或受影响记录有变化时，需复核新范围。
2. 保留页面中的页面和块引用会显示不可用。仍保留的记录会生成一个新修订，移除指向已删记录的关联。从旧修订或模板创建内容时，会跳过已删的关联目标。
3. 选择「检查附件清理」开始记录无引用原件的保留时间。七天后再次检查并确认，可清理仍无引用的文件。当前和归档页面、保留的历史和建议、模板或在途导入与备份需要的原件都会受到保护。原件重新被引用时结束本次保留期。

Windows 0.50.14 分页修复批次在断网客机实测七天保留期两侧。到期前确认按钮禁用，到期后仅清理无引用原件。清空前备份在独立空间恢复两份原件及父子页，重开保留修订。[分页修复批次复验](../.verify/windows-pdf-pagination-trash-0514/复验.md)

较早批次的 Windows 0.50.14 交接件已实装核对取消、清空、模拟到期后的清理及从清空前备份恢复。原生文件窗口恢复到独立空间后，原件与父子页修订均通过重开复查。[Windows 复验](../.verify/windows-current-trash-0514/复验.md)

## 工作空间升级失败

升级前，知页在数据根目录的 `upgrade-backups` 写入旧格式的 SQLite 快照和 `<工作空间 ID>-v<旧格式>.zhiye-recovery.zip`。这一目录可通过「备份与恢复 → 升级前备份目录」展开查看。升级准备或执行失败时，可在「无法打开的工作空间」查看错误与空间 ID。

检查备份目录的可用空间、权限及同名文件。SQLite 快照和整库 ZIP 均写入后才开始升级。若只出现 SQLite 快照，保留该文件，修复整库 ZIP 对应的写入问题后退出并重开知页。「无法打开的工作空间」面板也提供「备份与恢复」入口，可选择之前已验证的整库包。[升级故障与重试](Windows验收.md#a16-覆盖升级与独立恢复)

升级前的整库包可以用同一个恢复入口尝试在新空间打开。若校验拒绝损坏或未知结构，可选更早的已验证整库包。源空间升级后曾有新增内容时，先从源空间另存当前整库包，或保留该空间目录，再从升级前的包取回所需内容。
