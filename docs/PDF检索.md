# PDF 文本检索

在页面的「附件」中添加 PDF，或恢复包含 PDF 的工作空间。知页在打开该工作空间时提取附件的文字层。搜索支持中文、英文、短词和混合内容。结果显示原件名称、所在页面、页码和匹配片段。点击结果会打开原件对应的页码。

同一份 PDF 的不同页可以各自产生命中。正文或页面标题也命中时，正文和标题结果排在 PDF 之前。数据库筛选同样作用于该库记录中的 PDF 附件。

## 文件状态

| 附件列表显示 | 含义 |
|---|---|
| 等待提取 PDF 文本 | 文本提取在后台排队。搜索窗口也会显示待提取数量。 |
| 已索引 2/3 页 | 已检查三页，其中两页有可检索的文字。 |
| 部分提取 | 已发布成功提取的页或片段，其余部分在读取或达到上限时中止。 |
| 无文本层，未进行 OCR | PDF 只有图像或空白文字层，可通过附件预览继续阅读。 |
| PDF 加密，无法提取 | 原件需要密码。可以从附件面板另存，再按源文件授权处理。 |
| PDF 无法读取或提取 | 原件内容或文件读取失败。可重试索引，或从正常原件重新导入。 |
| PDF 超出提取上限 | 原件超过 24 MiB，或在扫描、文本容量或时间预算内未得到可用文字。 |

「搜索 → 重建索引」会重新处理本工作空间的页面和 PDF。提取最多访问前 2,048 页，每页保存最多 256 KiB UTF-8 文字，每份 PDF 最多保存 4 MiB 文字。单份 PDF 有 45 秒的提取预算。提取使用应用随附的 PDF.js Worker、字符映射和字体数据。[PDF.js 页文本接口](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html#streamTextContent)

## 原件与页码

搜索结果的「定位链接」可以复制到笔记或外部工具。链接包含工作空间、所属页面、附件 ID、SHA-256 和从 1 起算的原件页码。

```text
zhiye://open/workspaces/{workspace_id}/pages/{page_id}/attachments/{attachment_id}/pdf/{sha256}/{page_number}
```

附件改名会刷新搜索结果中的文件名，原件 ID、哈希和页码链接可继续使用。若链接所指的版本已不可用，知页打开所属页面并显示提示。归档期间，所属页与附件一起从当前搜索结果隐藏。恢复后可访问原件。原生 ZIP 保存原始 PDF、附件 ID 和 SHA-256，恢复后的新工作空间重新提取文本。

REST、SDK 和 MCP 只向拥有 `assets:read` 且有权读取所属页面的集成返回 PDF 摘要、附件 ID、原件哈希、页码、下载路径和索引进度。集成返回结果中的 `pdf.link` 可交给桌面定位，`pdf.content_path` 可获取原件。[本机 API](本机API.md#pdf-检索) [定位链接](定位链接.md)
