# 工作空间附件与存储迁移

本轮依据总计划 K13、K16、KB-004、KB-007、KB-014 与 A06／A07，贯通页面附件的导入、预览、另存和备份恢复，并验证旧 Demo 数据升级。

| 验收路径 | 实施位置 | 证据 |
|---|---|---|
| 旧工作空间升级 | Core 迁移脚本与 SQLite 在线备份 | 旧库有数据时原样升级。故意中止迁移后旧版本与快照仍可读。 |
| 持久化与重复导入 | Core 附件、Blob 文件与 SQLite 引用 | 中断读取不会写入附件。相同内容复用文件。独立空间互不读取附件。 |
| 原生包互通 | ZIP 格式 2 与 JSON 格式 1 导入 | ZIP 还原页面、历史、附件 ID 和内容。缺失或损坏的文件拒绝导入。 |
| 桌面流程 | Tauri 文件对话框、React 附件面板与本地 PDF.js | 文件加入页面后可查看，图片与 PDF 显示在应用内，其他格式可另存。 |
| 维护与交付 | 主计划、进度、格式、README 和锁文件 | 构建独立版本，实测后记入对应状态。 |

实现约定。附件归属于页面，具备独立 UUID。原件按工作空间内的 SHA-256 保持不可变。工作空间包使用未压缩 ZIP；校验清单与所有原件到齐后才发布导入目录。首期附件随回收站页面保留，页面的正文修订与附件独立。依赖、体积上限和旧库兼容方式随格式文档维护。
