# 知页最小桌面 Demo 实施计划

**目标**　用 Windows 桌面程序跑通建页、块编辑、SQLite 保存、重开和原生包恢复。

**架构**　Tauri 宿主通过 IPC 调用 Rust Core。每个工作空间单独存储，Rust 负责写入锁、事务、版本和导出。React 界面用 Tiptap 编辑，在边界转换为公开的块格式。

**依据**　[完整开发 Plan v2.0](../../../个人资源管理系统_完整开发Plan_v2.0.md) 第 2、4、5、7、8 章。本 Demo 验证 M0 和 M1 的核心操作。完整里程碑仍按总计划验收。

## 文件与任务

### 1. SQLite 核心与公开格式

`crates/core/src/model.rs` 定义 `Workspace`、`Page`、`PageDraft`、`Block`、`WorkspaceBundle`。`crates/core/src/store.rs` 提供 `Store::open`、空间与页面操作、修订与回收站、导入导出。`crates/core/src/markdown.rs` 处理通用导出。

- [x] 运行 `cargo test -p zhiye-core`，验证工作空间隔离、稳定 ID、写入冲突、页面环、重开、校验值及导出恢复。格式版本有读入检查。
- [x] 正文、修订和页面状态在同一事务写入。通过独占根目录锁保护单一写入者。导入新空间采用校验、暂存、发布三个步骤。
- [x] 将格式和恢复语义写入 `docs/数据格式.md`。

### 2. 桌面入口与编辑体验

`apps/desktop/src-tauri/src/main.rs` 处理 Tauri IPC 和本地文件操作。`apps/desktop/src/contracts.ts` 定义与 Core 对齐的类型。`apps/desktop/src/editor/` 处理块转换、编辑器和保存队列。`apps/desktop/src/App.tsx` 提供工作空间、页面树、搜索、历史、回收站和备份入口。

- [x] 测试块格式往返与保存队列，覆盖未知块、等待期间的新编辑和失败重试。
- [x] 界面可新建空间、根页面与子页，编辑标题和常用块，移动页面、搜索与查看历史。每页保存串行提交，切页、导出和退出前等待保存。
- [x] 使用系统文件对话框导出 Markdown 与原生包、导入原生包。导入创建独立工作空间，保留页与块 ID。

- [x] 更新 `README.md`、`开发进度.md` 和主计划中的实际交付状态。记录测试命令、可验证结果和待完成的 M0／M1 条目。

## 本轮主要验收风险

- 两个实例打开同一数据目录时，第二个实例可见失败，第一实例的数据保持完整。
- 第一次自动保存仍在提交时，后续输入不能被旧响应覆盖。提交失败保留可重试的草稿。
- 移动或导入不能形成页面环。导入失败不出现半份工作空间。
- 导入的陌生块保留原始内容，常用块与页面链接可跨导出恢复。
- 关闭并重开应用后，已保存的正文、稳定 ID、页层级和修订仍可查阅。
