# K02 页面图标与封面实施计划

依据 [开发方案 K02、K16 与 A07](../../../个人资源管理系统_完整开发Plan_v2.0.md) 完成页面外观。页面可从「页面操作 → 页面外观」更改图标，从本页图片附件选择或导入封面。封面显示在标题上方。普通页、数据库和记录使用同一入口。

## Core 与数据格式

- [x] 在 `crates/core/tests/page_appearance.rs` 驱动修订、附件归属、并发冲突、内容 ZIP 和整库恢复测试。
- [x] `Page` 增加可选 `cover`。`PageCover` 记录本页图片附件 ID 和 MIME 类型。SQLite 17 增加可空 `pages.cover`，按现有流程备份和迁移 SQLite 16。选择封面时使用附件实际 MIME，并沿用 24 MiB 图片预览上限。
- [x] `Store::set_page_appearance` 经现有页面提交入口保存图标和封面。同一修订也保存正文与属性。恢复历史时复制图标和封面，模板创建时用已分配的新附件 ID。
- [x] 内容 ZIP 含封面修订或模板时标记为 v6。沿用现有 v2 至 v5 的读取路径。整库恢复包继续由所含的 SQLite 版本判断兼容性。Markdown 在正文前输出有相对路径的封面图片。

## 桌面交互

- [x] `set_page_appearance` Tauri 命令返回已保存的 `Page`。页面外观对话框复用图标组件、附件读取和单图片文件选择。选择「无封面」只清除页面的封面引用。
- [x] 保存前提交正在编辑的标题和正文。保存成功后同步页面树和编辑区。加载封面使用已有的本机附件预览，历史窗口显示所选版本的图标和封面状态。
- [x] Chromium 用实际 Core 验证设置、清除、重开、历史恢复及导出。使用旧版生成的独立工作空间，在 macOS 原生窗口复验 SQLite 迁移和实际文件选择。回归 Rust、前端、REST v1 和 MCP，并在项目记录验收结果。
