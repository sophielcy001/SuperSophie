# K18 清空回收站

按[开发计划 v2.0](../../../个人资源管理系统_完整开发Plan_v2.0.md)第 2.2、5.1、5.3 和 6.2 节执行。本轮沿用当前项目目录、独立的 APFS 测试库和 SQLite／Tauri／React 验收入口。

- [ ] 用 `preview_empty_trash` 与 `empty_trash` 测试确认后新增或恢复页面时拒绝旧确认、写入失败时回滚整批、清空后活跃内容仍能正常编辑。清空使用一个 SQLite 写事务，并以当前回收站、相关记录的 ID 与修订生成确认值。
- [ ] 永久移除回收站页面及其正文、修订、记录、授权、索引和专属模板。存活页面中的页面链接指向原 ID 并显示不可用。用新修订清除存活记录指向已删除记录的关系。旧修订保持原值，恢复时过滤已删目标，计算定义和模板快照保留。只记录被删除的数据库、记录及其归属 ID，供校验和历史使用。SQLite 升到 19，涉及这些标识的内容包使用 ZIP v8。
- [ ] 验证归档后立即清空时，相关集成的旧增量游标失效并能重新编目。未受影响的集成继续使用游标。永久删除入口只在桌面。
- [ ] 对无引用附件原件使用工作空间级标记，确认最早观察时间满七天的对象后才清理。核对当前页、保留历史、回收站、待审建议和模板引用。用同一协调锁保护在途内容导出、备份和在事务外发布原件的导入。测试重新被引用、共享原件、旧包恢复、清理确认变化和重启。
- [ ] 接入回收站的清空和附件原件清理两个对话框，首次确认焦点设在取消或关闭上。用生产界面和真实 Core 运行取消、确认、重开及搜索验证。把过程、问题、可复验样本与结果写入当前目录。
